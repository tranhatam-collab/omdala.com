# Team 3 Bilingual Release Gate Design

Date: April 23, 2026
Owner: Team 3 (Gate, QA, Release)
Status: Active
Scope: `omdala.com` bilingual release authority

## 1. Goal

Define one deterministic release gate for bilingual readiness. No live decision can rely on verbal confirmation when evidence can be generated by scripts.

## 2. Gate architecture

### Layer A: Source integrity gate

Script:

- `scripts/bilingual-source-check.mjs`

Command:

- `npm run bilingual:source-check`

Pass behavior:

- `content/en.json` and `content/vi.json` parse
- `en` and `vi` tree shape matches
- required public pages exist in both `pages` and `publicPages`
- no empty/placeholder source strings
- public page views read from `getPublicPageBodyCopy`

Fail behavior:

- any source mismatch exits non-zero and blocks release

### Layer B: Public crawl gate

Script:

- `scripts/bilingual-public-audit.mjs`

Command:

- `npm run bilingual:public-audit`

Pass behavior:

- URL inventory includes `/` and every required `/vi/*` + `/en default path`
- one `<h1>` per audited public page
- title, description, canonical, hreflang, OG title, OG description exist
- schema includes name/description payload
- internal links keep active language route
- image alt is present and language-safe
- language switch mechanism maps equivalent route pairs

Fail behavior (release-blocking):

- missing metadata
- missing alt text
- language-switch equivalence mismatch

Non-blocking warnings are still reported for remediation backlog.

### Layer C: Product hard-code scan gate

Script:

- `scripts/bilingual-hardcode-scan.mjs`

Command:

- `npm run bilingual:hardcode-scan`

Scan scope:

- `apps/web`, `apps/app`, `apps/auth`, `apps/admin`, `packages/ui`

Ignored generated folders:

- `.next`, `out`, `node_modules`, `test-results`

Pass behavior:

- user-facing hard-coded literal findings are classified by owner (`Team 1`, `Team 2`, `Team 3`)
- Team 2 inventory handoff exists
- Team 2 unresolved `P0` findings count is zero

Fail behavior (release-blocking):

- Team 2 inventory artifact missing
- unresolved Team 2 `P0` findings > 0

### Layer D: Founder pre-live and decision gate

Script:

- `scripts/bilingual-founder-report.mjs`

Command:

- `npm run bilingual:founder-report`

Pass behavior:

- founder report is generated with required 10 sections
- Team 1 and Team 2 sign-off artifacts are read and evaluated
- final decision is deterministic `GO` or `NO-GO`

Fail behavior (release-blocking):

- any required sign-off or gate requirement is missing
- final decision is `NO-GO`

## 3. Release integration order

1. `npm run bilingual:source-check`
2. `npm run bilingual:public-audit`
3. `npm run bilingual:hardcode-scan`
4. `npm run bilingual:founder-report`
5. full runtime matrix (`pnpm release:verify` service checks)

If any bilingual gate step fails, release stops immediately.

## 4. Evidence outputs

All Team 3 scripts must write machine-readable evidence under:

- `reports/bilingual/`

Required latest pointers:

- `reports/bilingual/public-audit.latest.json`
- `reports/bilingual/hardcode-scan.latest.json`
- `reports/bilingual/founder-prelive.latest.json`

Human-readable output:

- `docs/OMDALA_BILINGUAL_PRELIVE_REPORT_2026-04-23.md`

## 5. Rule IDs and release effect

| Rule ID | Rule | Blocking |
| --- | --- | --- |
| `BL-GATE-A-01` | source check must pass | yes |
| `BL-GATE-B-01` | metadata completeness must pass | yes |
| `BL-GATE-B-02` | image alt completeness must pass | yes |
| `BL-GATE-B-03` | language switch equivalence must pass | yes |
| `BL-GATE-C-01` | Team 2 inventory handoff must exist | yes |

## 6. Decision authority

Only Team 3 can issue final bilingual release authority, and only when all blocking rules are green with evidence artifacts attached.

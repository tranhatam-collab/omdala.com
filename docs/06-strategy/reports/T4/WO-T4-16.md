- Production-default build: `out/monaco/vs` has 100 files (14 MB); `loader.config({paths:{vs:"/monaco/vs"}})` is called before the editor is created (`EditorPanel.tsx:15`, the only use of `@monaco-editor/react`).

- Negative control (served headers edited, then restored): removing `blob:` from `worker-src` made the spec fail with a `worker-src` violation ("Creating a worker from 'blob:…' violates … worker-src 'self'"). So the spec is sensitive to the policy it claims to test.
- Static scan of the built app: no jsDelivr, unpkg, googleapis or gstatic request anywhere. One chunk still contains the string `https://cdn.jsdelivr.net/npm/monaco-editor@0.55.1/min/vs`: it is the `@monaco-editor/loader` library's default config, overridden by `loader.config` before use; the browser run shows it is never requested. If another component ever uses the loader before that call, the CDN request would be blocked by CSP (fail closed), not served.
- Observation about my own run (not a defect): serving a staging-environment build with the production headers makes `connect-src` block `api-staging.omdala.com`; that is the pipeline rewrite above.
